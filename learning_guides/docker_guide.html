🚀 Tại Sao Nên Sử Dụng Docker?

Vấn Đề Truyền Thống

Trước khi có Docker, việc phát triển và triển khai ứng dụng gặp nhiều vấn đề:

Vấn Đề Mô Tả Hậu Quả
"It works on my machine" Ứng dụng chạy được trên máy dev nhưng không chạy trên server Mất thời gian debug, delay release
Environment differences Môi trường dev, staging, production khác nhau Bug khó lường trước, không ổn định
Dependency conflicts Xung đột phiên bản thư viện, framework Ứng dụng crash, khó maintain

🚀 Speed

🧠 Khái Niệm Cơ Bản

1. Container vs Virtual Machine

Aspect Virtual Machine Docker Container
OS Mỗi VM có OS riêng Chia sẻ OS của host
Size GB (vài GB đến vài chục GB) MB (vài MB đến vài trăm MB)
Startup time Phút Giây

2. Core Components

📦 Image

Template chứa code, runtime, libraries, config. Immutable và reusable.

🐳 Container

Instance của image đang chạy. Có thể start, stop, delete.

🏗️ Dockerfile

Script để build image từ base image và custom code.

⚙️ Cài Đặt Docker

Ubuntu/Debian

Ubuntu/Debian 
# Cập nhật package list
sudo apt update

# Cài đặt dependencies
sudo apt install apt-transport-https ca-certificates curl gnupg lsb-release

# Thêm Docker GPG key
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg

# Thêm Docker repository
echo "deb [arch=amd64 signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Cài đặt Docker Engine
sudo apt update
sudo apt install docker-ce docker-ce-cli containerd.io

# Khởi động Docker service
sudo systemctl start docker
sudo systemctl enable docker

Kiểm Tra Cài Đặt

Verify Installation 
# Kiểm tra Docker version
docker --version

docker info

# Chạy container đầu tiên

🔧 Lệnh Docker Cơ Bản

1. Quản Lý Images

Image Commands 
# Tải image từ Docker Hub
docker pull nginx:latest

# Xem danh sách images
docker images

# Xóa image
docker rmi nginx:latest

# Xóa tất cả images không sử dụng
docker image prune -a

2. Quản Lý Containers

Container Commands 
# Chạy container
docker run -d -p 8080:80 --name my-nginx nginx

# Xem containers đang chạy
docker ps

# Xem tất cả containers
docker ps -a

# Dừng container
docker stop my-nginx

# Khởi động lại container
docker start my-nginx

# Xem logs của container
docker logs my-nginx

# Truy cập vào container
docker exec -it my-nginx bash

🏗️ Tạo Dockerfile

Dockerfile Cơ Bản cho Node.js App

Dockerfile 
# Sử dụng Node.js 18 Alpine làm base image
FROM node:18-alpine

# Thiết lập working directory
WORKDIR /app

# Copy package.json và package-lock.json
COPY package*.json ./

# Cài đặt dependencies
RUN npm ci --only=production

# Copy source code
COPY . .

# Expose port
EXPOSE 3000

# Command để chạy ứng dụng
CMD ["npm", "start"]

Build và Run Image

Build Commands 
# Build image
docker build -t my-app:latest .

# Build với tag cụ thể
docker build -t my-app:v1.0.0 .

# Chạy container từ image
docker run -d -p 3000:3000 --name my-app-container my-app:latest

# Xem logs
docker logs my-app-container

🎯 Docker Compose

Docker Compose File Cơ Bản

docker-compose.yml 
version: '3.8'

services:
  # Web application
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DATABASE_URL=postgresql://user:password@db:5432/myapp
    depends_on:
      - db

  # Database
  db:
    image: postgres:15-alpine
    environment:
      - POSTGRES_DB=myapp
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=password
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"

volumes:
  postgres_data:

🎯 Best Practices

Security

Security Dockerfile 
# Sử dụng non-root user
FROM node:18-alpine
RUN addgroup -g 1001 -S nodejs
RUN adduser -S nextjs -u 1001
USER nextjs

# Không expose port không cần thiết
EXPOSE 3000

# Sử dụng multi-stage build
FROM node:18-alpine AS deps
# ... build steps

FROM node:18-alpine AS runner
# ... production steps

Performance Tips

🚀 Performance Tips:
  • Sử dụng .dockerignore để loại trừ file không cần thiết
  • Layer caching: copy package.json trước, sau đó mới copy source code
  • Multi-stage build để giảm final image size
  • Sử dụng Alpine Linux base images
  • Combine RUN commands để giảm layers

Production Checklist

⚠️ Production Checklist:
  • ✅ Sử dụng specific tags thay vì latest
  • ✅ Health checks cho tất cả services
  • ✅ Resource limits (CPU, memory)
  • ✅ Logging strategy
  • ✅ Backup strategy cho volumes
  • ✅ Monitoring và alerting
